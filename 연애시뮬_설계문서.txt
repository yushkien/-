────────────────────────────────────────────────────────────
S. 배경 설정 & 타임라인  ★게임의 시간 축
────────────────────────────────────────────────────────────

배경: 한국 고등학교 3학년 1년.
클라이맥스: 12월 25일 크리스마스 = 고백일 (하드 데드라인).
에필로그: 이듬해 2월 졸업식 = 최종 상태 평가 → 엔딩 표시.

설계적 의미:
  - 크리스마스(고백일)가 하드 데드라인 → "그 전에 관계를 완성해야 한다"는
    압박이 플레이어의 편애를 유도 → 질투·연합이 자연히 터진다.
    즉 "고백일 타이머"가 질투 시스템의 원동력.
  - 한국 고3 = 시간 희소(야자/학원/모평/수능).
    "슬롯을 누구에게 쓸까"라는 선택이 무거워진다 = 전략성.
  - 입시 압박 → 공부/연애 자원 배분 요소로 넣을 수 있음(선택적, 복잡도 주의).

연간 타임라인 (챕터 구분):
  시기                 분위기            역할
  ------------------   ---------------   ------------------------
  3~5월 (1학기 초)     도입, 관계 설정   히로인 소개, 초기 bond 체감
  6~8월 (여름/방학)    관계 심화         질투 싹트기 시작
  9~11월 (수능 임박)   긴장 최고조       ★연합/견제 폭발 구간
  11월 중순 수능       분기점            압박 해제, 연애 가속
  12/25 크리스마스     ★클라이맥스       고백 (하드 데드라인)
  2월 졸업식           ★에필로그         최종 상태 평가 → 엔딩

황금기:
  수능~크리스마스(약 한 달)가 "연애의 황금기".
  입시 압박이 풀리며 모두가 적극적으로 변함.
  질투 시스템이 이 구간에서 절정을 찍도록 설계하면 극적.

phase(국면)로 톤 전환:
  - 수능 전: 시간 희소 → 편애가 더 아프게 느껴짐 → 질투 상승 가속
  - 수능 후: 시간 풍부 → 관계 급전개 + 하렘 수용도 올릴 기회 집중
  → 글로벌 상태 phase(수능전/수능후)를 질투·호감 상승 배율에 곱해 구현.


────────────────────────────────────────────────────────────
0. 설계 철학 (가장 중요)
────────────────────────────────────────────────────────────

핵심 원칙: "루트를 미리 그리지 않는다. 상태를 보고 계산한다."

- 아마가미식 멀티 루트의 함정(루트 조합 폭발)을 피한다.
- 얀데레 시뮬의 매력("관계가 살아있는 느낌")은 가져오되,
  3D 모델링/실시간 AI 없이 2D 스탯 시뮬레이션으로 저비용 재현한다.

→ 로직(질투·연합·견제·엔딩)은 전부 "수치 규칙"으로 자동 계산.
→ 수작업 작업량은 오직 "이벤트 대사/CG 작성"에만 집중시킨다.
→ 그래서 콘텐츠가 늘어도 코드 복잡도는 늘지 않는다.

무엇을 자동화하고 무엇을 손으로 쓰는가:
  [자동/규칙]  질투 상승, 연합/견제 판정, 엔딩 결정
  [수작업]     초기 관계값 세팅, 각 이벤트의 대사·CG, 성격 파라미터 튜닝


────────────────────────────────────────────────────────────
1. 캐릭터 (히로인 4명)
────────────────────────────────────────────────────────────

연애 대상은 전원 여성. 남성 NPC와의 연애 분기는 없음.
모든 관계의 중심에는 플레이어가 있으나, 히로인끼리의 관계도
독립적으로 변동한다(연합/견제).

  A. 츤데레
     - 질투 상승 빠름. 겉으론 부정하면서 공격적으로 견제.
     - 표현과 실제 감정의 괴리가 큼.

  B. 메가데레(직구형)
     - 호감 상승 빠름. 숨김없이 들이댐. 질투도 솔직하게 표출.
     - 뒤끝이 없음(긴장 해소가 빠름).

  C. 소프트 얀데레
     - 평소엔 중간, 임계치를 넘으면 급변.
     - 임계 돌파 시 방해/사보타주가 과격해짐.

  D. 소심한 쿨데레
     - 느리게, 안으로 쌓는 타입.
     - 겉은 냉정(유대 유지)하지만 속으로 긴장 누적 → 뒤늦게 폭발.


────────────────────────────────────────────────────────────
2. 데이터 모델
────────────────────────────────────────────────────────────

2-1. 히로인 개별 상태 (플레이어 기준)
────────────────────────────────────────────
  Heroine:
    id
    name
    type              // 츤데레 / 메가데레 / 소프트얀데레 / 쿨데레
    affection    0~100 // 플레이어에 대한 호감
    jealousy     0~100 // 질투 게이지 (핵심 스탯)
    flags        {...} // confessed, saw_secret 등 개별 플래그

2-2. 히로인 간 관계 (방향성 쌍 모델)  ★핵심 설계
────────────────────────────────────────────
  설계 결정:
    - tension(긴장/질투)은 "비대칭(방향성)" 으로 둔다.
      → A가 B를 격하게 질투해도 B는 A에게 무관심할 수 있음.
    - bond(유대/친밀)는 "대칭" 으로 둔다(쌍당 1개).
      → "친구다"는 보통 상호적.

  Relationship(A, B):
    bond          -100 ~ +100   // 대칭. 초기값 수작업 설정.
    tension_AtoB     0 ~ 100     // 비대칭. A가 B에게 느끼는 질투/경쟁
    tension_BtoA     0 ~ 100     // 비대칭. B가 A에게

  데이터량 (히로인 4명):
    쌍 개수 = 6개 (AB, AC, AD, BC, BD, CD)
    각 쌍 = bond 1 + tension 2 = 값 3개
    총 18개 숫자 → 손으로 초기 세팅 가능.

    ※ 주의: 히로인 수가 늘면 쌍은 제곱으로 증가
      (3명→3쌍, 4명→6쌍, 5명→10쌍).
      로직은 동일하지만 견제/연합 "이벤트 텍스트" 작업량이 늘어난다.
      첫 작품은 4명으로 고정 권장.

2-3. 성격 파라미터 (성격을 로직에 곱해지는 수치로 변환)
────────────────────────────────────────────
  하나의 질투 로직을 쓰되, 캐릭터마다 다르게 "느껴지도록" 하는 장치.

  HeroineTraits:
    affection_gain       // 호감 상승 배율
    jealousy_gain        // 질투 상승 배율
    jealousy_threshold   // 질투 폭발 임계치
    tension_decay        // 긴장 해소 속도
    sabotage_power       // 방해 이벤트 위력
    hides_feelings       // 겉 표현과 실제 감정의 괴리 정도

  유형별 세팅 예시:
    A 츤데레     : jealousy_gain↑, hides_feelings↑
    B 메가데레   : affection_gain↑, tension_decay↑ (뒤끝 없음)
    C 소프트얀데레: threshold 돌파 시 sabotage_power↑
    D 쿨데레     : tension은 쌓이나 겉 bond 유지 → 뒤늦게 폭발

  효과:
    "웃으며 견제" 느낌 → 주로 B/D 에게서
    "과격한 방해"      → 주로 C 에게서
    "짝사랑성 라이벌"  → 방향성 tension으로 D→A만 높게 설정 등

2-4. 글로벌 상태
────────────────────────────────────────────
  GlobalState:
    day
    slot                 // 현재 턴 슬롯 (3-1 참조)
    phase                // 수능전 / 수능후 (질투·호감 배율에 영향, S 참조)
    harem_acceptance 0~100  // ★히든 스택. 하렘 엔딩 열쇠.


────────────────────────────────────────────────────────────
3. 턴(시간) 구조  ─ 복수 슬롯 방식(아마가미형)
────────────────────────────────────────────

하루를 복수의 슬롯으로 나눈다. 각 슬롯마다 1행동 선택.
  예) 평일 하루 = [방과후] / [야자] / [저녁]  (슬롯 3개)
  고3 특성상 "학원/야자"가 슬롯을 잡아먹는 설정으로 희소성을 연출 가능.

  시간 구조 (배경 S와 연동):
    1년 전체를 매일 플레이하지 않는다 → "이벤트성 날짜"만 플레이 턴으로.
    (예: 매주 1~2일 샘플링, 모평일, 방학 특정일, 수능 전후, 크리스마스)
    각 턴이 타임라인(3~5월 … 12/25)의 어디쯤인지 phase와 함께 표시.

  슬롯 단위로 행동 → 수치 변동 → 조건부 이벤트 체크가 돌아간다.
  "편애의 리듬"(누구에게 슬롯을 몰아주는가)이 질투·연합을 만든다.

  ※ 밸런싱 포인트: 복수 슬롯은 깊이가 있는 대신 밸런싱 난이도가 높다.
    질투가 몇 턴 만에 임계치를 넘는지 수치 곡선을 반드시 테스트할 것.


────────────────────────────────────────────────────────────
4. 핵심 루프 (매 슬롯마다 실행)
────────────────────────────────────────────

  (1) 플레이어가 행동 선택 (특정 히로인과 데이트/대화/공평행동 등)

  (2) 수치 반영
        - 선택된 히로인 A: affection += x * A.affection_gain

  (3) 질투 계산
        - A를 의식하는 히로인들: jealousy += y * jealousy_gain
        - (현장에 있거나 소문을 들었을 때)

  (4) 관계 긴장 계산
        - 질투가 높은 두 히로인 사이: tension(방향성) 상승
        - harem_acceptance가 높으면 tension 상승 완화 + bond로 전환 가능

  (5) 연합/견제 판정 (상태 평가 — 작성하지 않고 계산)
        독주자(leader) 판정:
          affection 1등이고 2등과 격차 > 25 인 히로인 L

        연합:
          tension_XtoL >= 60 인 히로인 X들을 모은다
          → X들끼리 bond가 낮아도(원래 안 친해도) 임시 'alliance' ON
          → 연합 방해 이벤트 풀 개방
          ("적의 적은 아군")

        웃으며 견제:
          bond(A,B) >= 40 AND tension_AtoB >= 60
          (원래 친했는데 질투로 틀어진 모순 상태)

  (6) 조건부 이벤트 발동
        조건을 만족한 이벤트가 "발생 가능 풀"에 떠서 재생된다.


────────────────────────────────────────────────────────────
5. 이벤트 시스템 (분기 트리 아님 → 조건부 풀)
────────────────────────────────────────────

  각 이벤트는 전제조건(requires)과 효과(effects)를 가진다.
  상태가 조건을 만족하면 발생 후보가 된다.

  예시 1) 방해 - 거짓 소문
    requires: C.jealousy >= 60 AND A.affection >= 50
    effects : A.affection -= 15, flag:rumor_spread = true

  예시 2) 웃으며 견제
    requires: bond(A,B) >= 40 AND tension_AtoB >= 60

  예시 3) 연합
    requires: 독주자 L 존재 AND tension_XtoL >= 60 (X 2명 이상)

  → "루트"를 짜는 게 아니라 "이벤트 카드"를 쌓는 방식.
    콘텐츠는 선형 증가, 조합 폭발 없음.


────────────────────────────────────────────────────────────
6. 하렘 수용도 (히든 스택)
────────────────────────────────────────────

  올라가는 조건(예):
    - 편애를 숨기지 않고 당당히 가는 선택
    - 모두에게 공평하게 대하는 선택
    - 질투 상황에서 "둘 다 좋아" 류의 선택
    - tension을 bond로 전환시키는 특수 이벤트 성공

  핵심 밸런스:
    수용도만 높다고 되는 게 아니다.
    히로인끼리 서로 받아들여야 하므로
    "모든 쌍의 tension이 낮게 유지"되어야 성립.
    → 하렘 엔딩이 자연히 "가장 어려운 엔딩"이 된다.


────────────────────────────────────────────────────────────
7. 엔딩 (작성하지 않고 최종 상태 평가로 결정)
────────────────────────────────────────────

  고백 → 에필로그 2단 구조:

  [1단계] 12/25 크리스마스 = 고백 (하드 데드라인)
    - 플레이어가 한 명을 지목해 고백 (하렘 조건 충족 시 "모두에게" 선택지 개방).
    - 고백 성공 여부 = 그 시점의 affection + 라이벌 방해 성공 여부로 판정.
    - 여기서 1차 결과(성공/거절/방해로 파투)가 갈린다.

  [2단계] 2월 졸업식 = 에필로그
    - 고백 결과 + 최종 상태(affection/jealousy/tension/harem_acceptance)를
      종합 평가해 최종 엔딩 장면을 보여준다.

  판정 순서(예):

    [하렘 엔딩] (최상위 난이도)
      harem_acceptance >= 70
      AND 모든 히로인 affection >= 60
      AND 모든 쌍 tension <= 30

    [개별 굿 엔딩]
      affection 최고 히로인 H 선택
      단, H를 겨냥한 라이벌의 방해가 성공했다면 → 배드/파국 분기

    [배드/파국 엔딩]
      편애 과다로 특정 히로인 jealousy·sabotage가 폭주하여
      관계가 붕괴한 경우

    [노멀/솔로 엔딩]
      아무도 임계치를 넘기지 못한 경우

  엔딩 수 가이드(첫 작품):
    개별 굿 4 + 하렘 1 + 배드 1~2 + 노멀 1  (≈ 7개)
    → 전부 "작성"이 아니라 "상태 조건"으로 분기되므로 관리 가능.


────────────────────────────────────────────────────────────
8. 작업량 / 복잡도 요약
────────────────────────────────────────────

  요소              방식                비용
  ---------------   -----------------   --------
  초기 관계값       수작업 (쌍 6개)     낮음
  질투 상승         수치 규칙           0(자동)
  연합/견제 판정    상태 평가 함수      0(자동)
  이벤트 대사/CG    수작업              ★여기가 진짜 작업량
  엔딩              최종 상태 평가      낮음

  결론: 코드가 아니라 "콘텐츠 양"으로만 규모가 늘어나는 건강한 구조.


────────────────────────────────────────────────────────────
9. 권장 범위 (첫 작품 기준)
────────────────────────────────────────────

  - 히로인 4명 (유형: 츤데레 / 메가데레 / 소프트얀데레 / 쿨데레)
  - 턴: 하루 복수 슬롯(예: 3슬롯) × 약 2주 ≈ 42턴
  - 엔딩 약 7개 (개별4 + 하렘1 + 배드1~2 + 노멀1)
  - 아트: 2D 스탠딩 + CG (프로토타입은 플레이스홀더 박스로 시작)

  개발 순서 제안:
    1) 데이터 구조 + 핵심 루프(수치만, UI 없이 콘솔) 먼저 돌린다
    2) 질투/연합/견제 수치 곡선 밸런싱
    3) 이벤트 카드 몇 장으로 수직 슬라이스
    4) UI / 아트 입히기


────────────────────────────────────────────────────────────
